# Бизнес Пульс: отдельная управленческая версия

Рабочая ветка: `feature/management-workspace`. Новые файлы находятся только в `management/`.
Действующий `main`, его `api/server.mjs`, GitHub Pages, база `pulse.db`, таймер и Quorum не изменяются.
Это самостоятельный сервер расширенной версии из того же репозитория, с собственной схемой и авторизацией.
Аккаунты и операции существующей версии автоматически не копируются.

## Реализовано

- Отдельный кабинет, адаптивный интерфейс, вымышленное демо без изменения реальной базы.
- Компания → точки → сотрудники, работа сотрудника в нескольких точках.
- Роли: владелец, директор, заместитель, руководитель точки, сотрудник, маркетинг.
- Приглашения, изменение роли и области доступа, отзыв доступа; действующие сессии сразу учитывают новые права.
- Ограничения компании/точек/личных результатов проверяются сервером. Контакты клиентов доступны на уровне компании владельцу, директору и заместителю. Маркетинг получает агрегаты без контактной базы.
- Продажи, чеки, средний чек, единицы, наполнение корзины, валовая прибыль/маржа, возвраты и скидки.
- Планы на компанию/точку/сотрудника/категорию/товар, равномерный план к дате, прогноз темпа, версии планов.
- Разбор изменения продаж по чекам, наполнению и средней цене/составу покупок. Симметричный факторный разбор (Shapley) сходится с общим изменением. Основа сравнения — предыдущий равный период, не гипотетические плановые факторы. Наличие продаж не доказывает полноту загрузки периода.
- Справочники товаров и категорий, разрезы по точкам и сотрудникам.
- Карточки клиентов: телефон, email, внешние ID, теги, заметки, явные согласия по каналам; внешняя программа лояльности, карта, уровень и снимок баланса на дату.
- Кампании/акции: цели, точки, товары, период, промокод, бюджет, расходы и явно связанные покупки. Расходы вычитаются из валовой прибыли только при полном охвате срока и всех точек кампании. Связанные продажи не называются причинным эффектом рекламы.
- Локальное чтение CSV (UTF-8/Windows-1251) и XLSX, выбор листа и сопоставление столбцов, выбор рублей/копеек; JSON. До 5000 строк/4 МБ JSON в запросе, файл до 16 МБ. XLSX без внешнего CDN, нужен браузер с `DecompressionStream('deflate-raw')`. Парсер ограничивает распаковку; `.xls` не поддерживается.
- Приём справочников и продаж через API, стабильные ID, повторное обновление/отмена, атомарная проверка пакета, отзыв ключей и журнал успешных синхронизаций.
- Краткий разбор по правилам; при `BPM_OPENAI_API_KEY` — анализ обезличенных агрегатов через OpenAI с кешем 10 минут, таймаутом и fallback. Контакты, имена клиентов/сотрудников и заметки не входят в запрос.

## Границы этой версии

Готовых коннекторов к сторонним сервисам пока нет: реализованы входящий API и справочники для интегратора.
Остатки, полноценный складской учёт, собственное начисление/списание бонусов на кассе, рассылки, медицинская маршрутизация и маркетинговые контракты не реализованы.
Старые клиентские когорты/LTV остаются в действующей версии; в новом кабинете пока покупки и денежные показатели клиентов за выбранный период.
Нет автоматического объединения контактов и переноса старой базы. Изменение названия/категории товара меняет группировку исторических продаж; себестоимость фиксируется в строке продажи.
Владельцы не создаются публично: первичный доступ выдаёт оператор. Сброс пароля через email и SMTP не подключены.

## Локальный запуск (Node 22.21.1+)

```bash
BPM_DB_FILE=/tmp/bp-management/management.db BPM_ORIGIN=http://127.0.0.1:3128 node management/server.mjs
```

Откройте `http://127.0.0.1:3128`, затем «Посмотреть пример». Для полноценного кабинета создайте владельца в отдельной базе:

```bash
export BPM_DB_FILE=/tmp/bp-management/management.db
export BPM_COMPANY='Моя компания' BPM_OWNER_NAME='Владелец' BPM_OWNER_EMAIL='owner@example.com'
read -r -s -p 'Пароль (от 12 символов): ' BPM_OWNER_PASSWORD
export BPM_OWNER_PASSWORD
node management/owner.mjs
unset BPM_OWNER_PASSWORD
```

Пароль не передаётся в аргументах процесса, не хранится в репозитории; в БД — scrypt и случайная соль.
Сессия: HttpOnly, SameSite=Strict, Secure при HTTPS; изменяющие запросы кабинета проверяют Origin.
Не используйте старый `BP_DB_FILE`: новый процесс явно запрещает `pulse.db` и совпадение с `BP_DB_FILE`.

## Входящий API

Ключ создаётся владельцем/директором в разделе «Данные и интеграции» и показывается один раз.
Он даёт запись справочников и продаж только в выдавшую компанию. Хранится только хеш ключа.

### 1. Справочники

`POST /businesspulse/api/v1/catalog`, `Authorization: Bearer KEY`, `Content-Type: application/json`:

```json
{
  "source": "my-pos",
  "entities": {
    "locations": [{"external_id":"shop-1","name":"Центральная"}],
    "employees": [{"external_id":"person-1","name":"Сотрудник","location_refs":["shop-1"]}],
    "products": [{"external_id":"sku-1","name":"Крем","category":"Уход","unit":"шт.","sku":"ART-001"}],
    "customers": [{"external_id":"client-1","name":"Клиент","phone":"+79991234567","external_ids":{"pos":"client-1"},"loyalty":{"program":"Клуб","balance":100,"as_of":"2026-11-08"},"consents":[]}]
  }
}
```

До 1000 объектов в пакете. Ответ содержит для каждого внешнего ID постоянный внутренний `id`.
Повторная отправка по `(company, source, kind, external_id)` обновляет объект.
`location_refs` сотрудников — внешние ID точек из того же источника.
ID клиента не объединяется с совпавшим телефоном автоматически.

### 2. Продажи

`POST /businesspulse/api/v1/sales`, те же заголовки. Используйте внутренние ID из ответа справочников:

```json
{
  "source":"my-pos",
  "rows":[{
    "external_id":"sale-100-line-1",
    "receipt_id":"sale-100",
    "date":"2026-11-08",
    "location_id":"LOCATION_ID",
    "employee_id":"EMPLOYEE_ID",
    "product_id":"PRODUCT_ID",
    "customer_id":null,
    "campaign_id":null,
    "status":"sale",
    "quantity":2,
    "amount_kopecks":100000,
    "cost_kopecks":60000,
    "discount_kopecks":5000
  }]
}
```

Сумма — итог строки после скидки; себестоимость — всей строки, не единицы. Суммы и количество положительные, направление определяет `sale`/`refund`. `cost_kopecks:null` означает отсутствие себестоимости, не ноль.
Отмена ранее отправленной строки: `{ "external_id":"sale-100-line-1", "status":"cancelled" }`.
Отсутствие строки в очередной выгрузке ничего не удаляет. Для одного чека несколько строк должны иметь разные `external_id`.
Источник должен быть один и тот же при передаче файла и API, если это одни операции: разные источники считаются разными книгами и автоматически не сверяются.
Себестоимость возврата передаётся источником. Поступления, авансы и долги сюда не загружаются: этот модуль учитывает выполненные продажи.

## Отдельное развёртывание на VPS

Целевой адрес: **https://cityai.site/businesspulse/**. Новая DNS-запись и новый TLS-сертификат не нужны: используется существующий HTTPS cityai.site.

1. Выполнить `management/deploy/install-service.sh` от root. Устанавливает только новый каталог `/opt/business-pulse-management`, пользователя, службу и БД `/var/lib/business-pulse-management/management.db`. Существующие каталоги не перезаписывает. Проверено на Node 22.21.1 и Node 24; используется Node по существующему пути `/usr/local/bin/node-business-pulse`.
2. Выполнить `bash /opt/business-pulse-management/management/deploy/create-owner.sh` от root. Скрипт запрашивает данные и создаёт владельца от имени нового пользователя, не выводя пароль.
3. Для проверенного конфига с маршрутом `/quorum` выполнить `bash /opt/business-pulse-management/management/deploy/install-route.sh`. Скрипт добавит два location в существующий HTTPS-блок, сохранит копию в `/var/backups/business-pulse-management`, проверит Nginx и HTTPS health; при ошибке восстановит конфиг. При отличающейся структуре остановится без правок. `nginx.conf` — snippet, не отдельный server-блок.
4. Проверить `https://cityai.site/businesspulse/api/health`, демо, вход, создание точки/плана, загрузку, права сотрудника. Старый `pulse.cityai.site` проверить отдельно.

Конфигурация: `/etc/business-pulse-management/app.env` (0600):

```ini
BPM_ORIGIN=https://cityai.site
BPM_BASE_PATH=/businesspulse
```

Необязательно `BPM_OPENAI_API_KEY`, `BPM_AI_MODEL`. Не подключайте env старого бота или платёжного сервиса. Путь учитывается в ссылках, API, приглашениях и cookie; Nginx передаёт его без обрезания.
Автодеплой старого приложения продолжает следить только за main. Для автоматического обновления выполните `bash /opt/business-pulse-management/management/deploy/install-autodeploy.sh`. Таймер проверяет `feature/management-workspace` каждые 30 секунд. Проверки запускаются в отдельном временном каталоге от имени пользователя приложения; затем останавливается только management-служба, делается SQLite backup и обновляется код. При провале health-check возвращаются предыдущий код и база. Неудачный SHA не повторяется до следующего коммита. Локальные правки и non-fast-forward блокируют обновление. Nginx, старый Business Pulse и Quorum не обновляются. Бэкапы и состояние: `/var/lib/business-pulse-management/deploy-state`. Журнал: `journalctl -u business-pulse-management-deploy.service -n 50 --no-pager`.
Ссылка с главной cityai.site в этой ветке не меняется: исходники главной находятся вне этого репозитория.

## Проверки

```bash

```

Можно указать `BPM_PLAYWRIGHT_MODULE` и `BPM_CHROMIUM_PATH` для уже установленного браузера. Проверяются настольный и мобильный интерфейсы, создание точки/плана/клиента, CSV-импорт, разбор, принятие приглашения и ограничение руководителя точки.

## Демонстрация из своего кабинета

Кнопка **Демо** в шапке создаёт отдельное представление на основе доступных пользователю точек, товаров, категорий, сотрудников и планов. Продажи и клиенты генерируются в памяти, контакты и реальные операции не копируются и не меняются. Все изменения в демо отключены. Показатели, графики, сравнения и планы можно показывать на скриншотах; плашка обозначает синтетические данные. **Вернуться** возвращает в реальную компанию. Если точек или товаров ещё нет, открывается общий пример. Для защиты ресурсов пример использует до 12 точек, 40 товаров и 120 сотрудников, история ограничена демонстрационным диапазоном. Демо на своей структуре требует действующей авторизации.

## Продажи и ассортимент

Раздел **Продажи** отделён от справочника. Выбор точки доступен как общим фильтром, так и внутри отчёта; из результатов точек на главной можно перейти к её категориям и товарам. Категория открывает товары, товар — сравнение по точкам. Режим «По каждой точке» показывает отдельные строки «точка × категория/товар».

Показатели сгруппированы в наборы «Основное», «Чеки и количество», «Цены и скидки», «Прибыль»: продажи и изменения ₽/%, проданные и возвращённые единицы, нетто, чеки с объектом и доля чеков, средняя цена после скидок до возвратов, скидки, возвраты, себестоимость, валовая прибыль/маржа, прибыль на единицу. Вклад количества и цены/состава рассчитывается симметрично и сходится с изменением нетто-продаж. По категориям ценовой вклад включает состав продаж, а не только изменение прайс-листа. Средняя сумма объекта в чеке не равна полному среднему чеку. Доли чеков пересекающихся товаров/категорий не суммируются; знаменатель — все чеки доступной сети или выбранной точки. Количество и средняя цена не суммируются при несовместимых единицах.

Сравнение — предыдущий равный период. Товары, присутствовавшие в предыдущем периоде и отсутствующие в текущей выгрузке, сохраняются в таблице. Если в одном из периодов нет операций по доступному срезу, вывод о снижении не делается. Неполные выгрузки не подтверждают физическое отсутствие продаж или остатков. Анализ учитывает выбранные точку, категорию и товар; расчёты и сортировка просадок не требуют ИИ.

**Ассортимент** — отдельный раздел: поиск по названию, SKU/артикулу, внутреннему ID и кодам учётных систем; фильтр категории, страницы по 50 записей, создание и редактирование товара. Внутренний ID сохраняется автоматически; SKU необязателен. Внешние коды показываются из сопоставлений `source + external_id`, созданных `/api/v1/catalog`. При обновлении интеграцией отсутствие поля `sku` не стирает существующий артикул. CSV/XLSX может ссылаться на товар по ID, точному названию, уникальному SKU или внешнему коду; неоднозначное совпадение отклоняется.

API кабинета: `GET /businesspulse/api/products?q=...&category=...&page=1&page_size=50` и `GET /businesspulse/api/sales?from=...&to=...&location_id=...&category=...&product_id=...&group=category|product|location&layout=summary|locations&sort=sales|sales_delta|profit_delta|quantity_delta|name&page=1`. Все разрезы ограничены правами пользователя. Для демо аналогичные маршруты `/api/demo/products` и `/api/demo/sales`, параметр `configured=1` требует входа. Новое поле SKU добавляется миграцией без замены существующих товаров и операций.

## Интерактивный график

Плитки продаж, чеков, среднего чека и валовой прибыли переключают график в обзоре и в разделе продаж. Активный показатель выделяется. График показывает выбранный период, ось сумм/количеств, даты и точки. При наведении, касании и выборе стрелками значение и дата обновляются в постоянной строке под графиком, без всплывающего тултипа. До 45 дней используются дни, до 180 — интервалы по 7 дней, далее — календарные месяцы с обрезкой по границам периода. Средние пересчитываются из операций каждого интервала. Дни без операций подписываются как отсутствие операций в загрузке; будущие интервалы и неизвестная себестоимость не заменяются выдуманными значениями.
