# Локальный автодеплой «Бизнес Пульс» — как в CityAI

На VPS работает отдельный systemd-таймер `business-pulse-deploy.timer`. Раз в 15 секунд после предыдущей проверки он сверяет SHA ветки `main` публичного GitHub-репозитория через `git ls-remote`. Если commit новый, запускает собственный скрипт развёртывания. **GitHub Actions, GitHub SSH-секреты, ключи и GitHub CI не используются.** Стандартный GitHub Pages публикует Mini App отдельно.

## Один раз настроить на VPS

Выполнить от root:

```bash
cd /opt/business-pulse
git pull --ff-only origin main
bash deploy/install-poller.sh
```

Установщик копирует в root-owned `/usr/local/sbin/` два скрипта (`business-pulse-poll`, `business-pulse-deploy`), ставит **отдельные** `business-pulse-deploy.service` и `business-pulse-deploy.timer`, выполняет первый деплой с резервной копией базы и лишь после успеха включает таймер.

## Проверка

```bash
systemctl status business-pulse-deploy.timer --no-pager -l
systemctl list-timers --all | grep business-pulse
journalctl -u business-pulse-deploy.service -n 40 --no-pager
curl -sS https://pulse.cityai.site/api/health
```

Остановить только автоматическое развёртывание Бизнес Пульс:
`systemctl disable --now business-pulse-deploy.timer`.
API и Telegram-бот продолжат работать.

## Защита данных при развёртывании

- Запускаются проверки синтаксиса и Node.js тесты; изменение, не прошедшее их, не активируется.
- Перед миграцией SQLite останавливаются **только** службы `business-pulse-api` и `business-pulse`, и сохраняются `pulse.db` и журналы WAL/SHM в `/var/lib/business-pulse/backups/`.
- Скрипт проверяет `/api/health`, затем запуск Telegram-бота. При ошибке восстанавливает БД и прежнюю версию Git.
- Неудачный SHA не выкатывается снова каждые 15 секунд; повторная попытка будет после нового коммита.
- CityAI, его PM2, БД, Nginx, service и timer никак не затрагиваются.
- Маркер развёрнутой версии: `/var/lib/business-pulse/.deployed-commit`.

Таймер лишь проверяет GitHub. Если SHA не изменился, он не скачивает код и не перезапускает сервисы.

**Примечание о безопасности:** обновление root-owned управляющих скриптов `deploy/release.sh` и `deploy/poll.sh` потребует повторного ручного запуска `bash deploy/install-poller.sh`. Обычный код API, бота и Mini App обновляется автоматически. Это не даёт случайному изменению GitHub прямого доступа к управляющим root-скриптам.

## Накопительный импорт

CSV теперь **дополняет** старые записи, а не стирает их. Идентификатор строки: дата, стабильный ID чека/визита, позиция, статус и порядковое вхождение повторяющейся позиции. Повторная загрузка не увеличивает сумму; изменённая сумма обновляется. Агрегаты и отчёты пересчитываются из накопленной истории. Перед первым деплоем API мигрирует имеющиеся строки, сохраняя их.

Ограничения MVP: удаление записей, исправление даты операции и дубли позиций с изменяемым порядком требуют отдельной сверки или собственного `line_id`. Файлы без постоянного ID чека для накопительного импорта не годятся. Не загружайте персональные и медицинские данные без соответствующих разрешений и мер защиты.
