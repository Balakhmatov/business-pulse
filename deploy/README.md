# Автодеплой «Бизнес Пульс»

Настройка один раз. После неё push в `main` автоматически запускает тесты и обновляет **только** `business-pulse-api` и `business-pulse` на VPS. Никакой проверки по таймеру нет. GitHub Pages продолжает публиковать Mini App самостоятельно.

## 1. Отдельный SSH-ключ на Windows

В PowerShell:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\business-pulse-ci" -C "business-pulse-github"
scp "$env:USERPROFILE\.ssh\business-pulse-ci.pub" root@194.31.174.8:/root/business-pulse-ci.pub
```

Для ключа GitHub Actions не задавайте passphrase (два раза Enter при запросе), иначе автоматическая работа потребует интерактивного ввода. **Приватный ключ никому не пересылайте и не добавляйте в git.**

## 2. Установить ограниченный доступ на VPS

Подключиться к VPS как root:

```bash
cd /opt/business-pulse
git pull --ff-only origin main
bash deploy/install-ci.sh /root/business-pulse-ci.pub
```

Скрипт создаёт только пользователя `bp-deploy`. Ключ ограничен принудительным запуском **одной** root-owned команды `/usr/local/sbin/business-pulse-deploy`; произвольный SSH-shell недоступен. Скрипт показывает строку публичного SSH-ключа хоста для GitHub. Не используйте произвольный `ssh-keyscan` вместо проверки реального ключа сервера.

## 3. Секреты и переменная в GitHub

В репозитории `Balakhmatov/business-pulse` → Settings → Secrets and variables → Actions → **Repository secrets**:

- `BP_DEPLOY_SSH_KEY`: полный **приватный** ключ из `$env:USERPROFILE\.ssh\business-pulse-ci` (включая строки BEGIN/END).
- `BP_DEPLOY_KNOWN_HOSTS`: полная строка `194.31.174.8 ssh-ed25519 AAAA...`, выведенная скриптом установки на VPS.
- `BP_DEPLOY_HOST`: `194.31.174.8`.

После добавления **всех трёх** секретов в Repository variables создать `BP_DEPLOY_ENABLED` со значением `true`.

Затем в GitHub → Actions → **Business Pulse CI and deploy** → Run workflow → `main` запустить первый деплой. Дальше всё происходит при каждом push в `main`, если изменён код API, бота, сайта или деплоя.

## 4. Защита существующих данных

`deploy/release.sh`:

- блокирует параллельные деплои;
- проверяет чистоту Git и fast-forward;
- останавливает только два сервиса «Бизнес Пульс»;
- создаёт согласованную резервную копию SQLite (`pulse.db`, `-wal`, `-shm`) в `/var/lib/business-pulse/backups/`;
- проверяет JS и тесты на VPS перед запуском;
- ждёт `/api/health`, проверяет бот;
- при ошибке возвращает предыдущий commit и базу из резервной копии.

CityAI, его Nginx, служба и БД не затрагиваются. У бота сохраняются подписчики в отдельном JSON.

Ограничение: обновление **самого root-owned деплой-скрипта** требует отдельно повторить второй шаг, чтобы обновить доверенную копию. Это сделано намеренно: изменение файла в git не должно автоматически давать новые root-полномочия.

## 5. Правила накопительного импорта

Новый CSV **не удаляет** старые операции. Для совпадения используются дата, стабильный ID чека/визита, товар/услуга, тип (продажа/возврат) и номер повторения одинаковой позиции внутри чека. В рамках одного источника новая сумма той же операции обновляется. Прежние файлы можно загрузить повторно, они не должны удваивать выручку.

**Ограничения:** отсутствие стабильных ID, изменение даты уже сохранённой операции, полная отмена/удаление записи и несколько разных строк одной позиции внутри одного чека без собственного line ID требуют отдельной сверки или расширения схемы. Такие ситуации нельзя автоматически считать корректными. Импортированный файл не должен содержать персональные/медицинские данные без необходимых оснований и защиты.
